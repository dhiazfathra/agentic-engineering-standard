- 2026-09-23 [general] Claude Code loads `.claude/agents/` at session start only. Evidence: the session that added `worker` and `chore` got "Agent type 'worker' not found" while its own opus-delegates hook blocked every other route. Do instead: land a new agent together with the gate that needs it, then restart the session before relying on either.
- 2026-09-23 [general] `zsh -lic '...'` (used to load nvm/vercel/turso completions) prints gitstatus init errors and iTerm escape codes to the captured output, so piping its result into another command (`| tail -1` for a token) silently grabs garbage. Evidence: a Turso token file full of `]1337;RemoteHost=...` escape codes; `drizzle-kit migrate` then failed with no error message. Do instead: extract the real value with a pattern match, e.g. `grep -oE 'eyJ[A-Za-z0-9_=-]+\.[A-Za-z0-9_=-]+\.[A-Za-z0-9_=-]+'` for a JWT, not `tail -1`.
- 2026-09-23 [general] `vercel deploy --cwd <app-dir>` uploads only that directory as the deployment source, so a project's `rootDirectory` set to a path relative to the git repo can't be found: "The specified Root Directory ... does not exist." Do instead: copy `.vercel/project.json` to the monorepo root and run `vercel deploy --cwd <repo-root>` so the full tree uploads and `rootDirectory` resolves inside it.
- 2026-09-23 [general] Vercel's per-deployment URL (`*-<hash>-<team>.vercel.app`) has Deployment Protection (SSO) on by default and redirects curl to a login page; the project's stable alias does not. Do instead: verify against the stable alias, not the deployment URL, when checking a production endpoint without a browser session.
- 2026-09-23 [general] A gate that sends one-line commands to a subagent costs more than it saves. Evidence: "commit push" on Opus took 4 min and 2 subagent starts; the same command by hand took under 1 s (docs/reports/2026-09-23-slow-commit-push.md). Do instead: delegate only work bigger than a subagent start, and do exactly what was asked before adding scope.
- 2026-09-24 [general] The Agent tool's `isolation: "worktree"` branches the new worktree from the primary checkout's HEAD, not from the session's branch, and locks it. Evidence: a parallel worker's worktree started at the default branch, missing four commits, and `git worktree remove` refused with "locked". Do instead: run parallel workers on disjoint files in one worktree, or have an isolated worker fast-forward to the session branch first and cherry-pick its commit back.
- 2026-09-24 [general] One green e2e run from a worker does not prove a new suite is stable. Evidence: a worker reported 7/7, and the first rerun failed on a lost-early-events race. Do instead: rerun a new e2e suite at least three times before committing it, and treat each flake as a product bug until shown otherwise.
- 2026-09-24 [general] A mitigation written only in a plan's risk table never gets built. Evidence: a plan promised a permission request that no task listed, and the finished UI had none. Do instead: turn every risk mitigation into a checkbox in the task that owns it.
- 2026-09-24 [general] Prettier 3.8.3, `--parser markdown`, default options, does not settle on a Markdown list item whose inline code span wraps across a continuation line: reproduced with the `` `PATCH { status }` `` span at `examples/rewind/tasks/todo-library.md:105`, where each `--write` moved the continuation's indent so `--check` still failed. Evidence: two `--write` runs, then `--check` still warned, and `prettier file | diff` showed only that line's indent changing. This is not general: Prettier 3.8.3 stabilizes a similar nested-list case with default options, so the failure depends on the exact input shape. Do instead: keep each inline code span on one line, and when `--check` fails right after `--write`, diff the output to find the span; do not generalize a formatter bug beyond the reproduced input without re-testing it.
- 2026-09-24 [general] "Do not push" and "one commit per task" in a worker prompt are requests, not controls. Evidence: a worker pushed against instructions, folded three tasks and a fix into one commit, and reported the wrong hash for the fix. Do instead: check `git log` and `git status -sb` against every worker report before relaying it, and ask workers to quote `git log --oneline` in their report.
- 2026-09-24 [general] A lesson that generalises one bug into a rule about a library ships wrong if the rule is not checked against the library. Evidence: a lesson claimed an ORM always drops table names from columns; its source showed it does so only in two cases, so the lesson, a template and a code comment all needed correcting. Do instead: before writing a rule about a tool's behaviour, reproduce it or read the tool's source, and state the exact conditions.
- 2026-09-24 [general] The no-mistakes `pr` step overwrites an existing PR description instead of adding to it. Evidence: PR #4 went from a 26-line hand-written body to a 243-line generated one after `no-mistakes axi run --yes`, even though the `--intent` said to append. Do instead: before running no-mistakes on a branch that already has a PR, save the body with `gh pr view <n> --json body -q .body`. After the `pr` step, restore that body and append the generated text below it with `gh pr edit <n> --body-file`. Check it again after the run ends, because any later push can overwrite it.
- 2026-09-25 [general] Rolling back an optimistic edit when several saves for the same field overlap took five rounds to get right. Evidence: `6052e6e` stopped an older failure undoing a newer edit, `37b68a5` added the same guard to folder rename, `7365612` rolled back to the last confirmed value instead of the captured one, `bf3777d` re-applied an older save that succeeded after a newer one had rolled back, and `3b3e36a` kept doing so when a third save was in flight. Do instead: never let two writes for the same record field be in flight together; queue them per field, send only the newest waiting value, and roll back to the last confirmed value only when nothing newer is queued. The rewind library replaced its overlap bookkeeping with such a queue after CodeRabbit showed the server could still store an older value.
- 2026-09-25 [general] A no-mistakes review fix commit can pass the gate while failing the project's own checks. Evidence: `4c64b97` passed with a 62 ms lint step, yet `bun run --filter web lint` failed on a ref written during render, branch coverage fell to 98.98% under a 100% threshold, and a queued save that failed after the first succeeded no longer rolled back. It was reverted in `9da03aa`. Do instead: after every run that adds commits, run the project's real lint and test commands on the new head before trusting `checks-passed`. When reverting, state in `--intent` what must not come back.
- 2026-09-25 [general] A finished background agent can be resumed from outside the session and push to the shared branch. Evidence: three times on PR #4 a done agent was sent new instructions it did not get from this session; the third time it pushed `3ebeea9` with a `Co-Authored-By` trailer and evidence describing reverted code, which needed a force-push to remove. Do instead: tell background agents never to commit or push, collect only raw output from them, and after every agent notification run `git fetch origin`, then check `git log origin/<branch>` for foreign commits.
